# Step 29: Minimal PCI Driver—probe and remove

> **Phase F: Linux PCI Driver**
>
> Phase E built the device model on the VMM side. Phase F writes the driver on the guest-kernel side.
> Together, these complete both sides of a virtual PCI device: hardware emulation and the software that operates it.

## Goal

Create a minimal Linux kernel module matching the microkvm PCI device (vendor 0x1234, device 0x0001), and verify that `insmod` automatically invokes `probe`.

## Background

### Connecting Phase E and Phase F

Phase E implemented the *device*: the VMM returns vendor=0x1234 and device=0x0001 for config-space reads. Phase F implements the *driver*: a guest kernel module declaring that it handles those IDs.

Vendor/Device IDs connect the two:
```
VMM (pci.c):     config[0x00] = 0x1234, config[0x02] = 0x0001
Driver (.c):     #define MICROKVM_VENDOR 0x1234, #define MICROKVM_DEVICE 0x0001
```

Without an ID match, the PCI core does not call probe. Physical-device drivers work the same way.

### Linux PCI driver lifecycle

```
1. Boot: PCI bus scan reads vendor/device IDs from each slot's config space
2. insmod: driver registers its ID table through pci_register_driver()
3. Match: PCI core finds a matching device
4. Probe: driver's probe() is called to initialize the device
5. rmmod: remove() is called to release the device
```

### The module_pci_driver macro

```c
module_pci_driver(microkvm_pci_driver);
```

Expands to `module_init` + `module_exit` + `pci_register_driver` / `pci_unregister_driver`, eliminating boilerplate for a simple PCI driver.

### Out-of-tree module build

```makefile
obj-m := microkvm_pci.o
KDIR := $(HOME)/linux-src

all:
    $(MAKE) -C $(KDIR) M=$(PWD) modules
```

`-C $(KDIR)` delegates to the kernel Makefile. `M=$(PWD)` requests a module build for this directory. `Module.symvers`, generated by `make modules` in the kernel tree, is required.

## Execution flow

```
Guest (insmod)               PCI Core                  VMM
──────────────               ────────                  ───
insmod microkvm_pci.ko
  → pci_register_driver()
                             Scan device list
                             device 0000:00:00.0
                               vendor=0x1234 ✓
                               device=0x0001 ✓
                             → Call probe()

probe():
  dev_info("probe called")
                                                       (This probe only logs;
                                                        it does not access PCI BARs)

rmmod microkvm_pci
  → pci_unregister_driver()
    → remove()
```

## Implementation

### Prerequisites

Run the following on the host, assuming guest kernel sources in `~/linux-src` and microkvm in `~/microkvm`. Build the driver against the same kernel build tree used for the guest.

**1. Enable kernel configuration and rebuild**

Enable the kernel options needed throughout Phase F (Steps 29–32) together.

```bash
$ cd ~/linux-src
$ scripts/config --enable CONFIG_MODULES
$ scripts/config --enable CONFIG_MODULE_UNLOAD
$ scripts/config --enable CONFIG_PCI_MSI
$ make olddefconfig

# Confirm all are =y
$ grep -E 'CONFIG_MODULES=|CONFIG_MODULE_UNLOAD=|CONFIG_PCI_MSI=' .config

$ make -j"$(nproc)" bzImage
$ make -j"$(nproc)" modules
$ cp arch/x86/boot/bzImage ~/microkvm/bzImage
```

`make modules` also generates `Module.symvers` for resolving external-module symbols.

**2. Build the driver**

```bash
$ cd ~/microkvm/driver
$ make
$ ls -l microkvm_pci.ko
```

**3. Include it in initramfs**

Extract the existing initramfs into a new working directory, add the `.ko` and BusyBox links for module commands, then repack.

```bash
$ initramfs_work=$(mktemp -d /tmp/microkvm-initramfs.XXXXXX)
$ cd "$initramfs_work"
$ sudo sh -c "zcat $HOME/microkvm/initramfs.gz | cpio -idm"
$ sudo cp ~/microkvm/driver/microkvm_pci.ko lib/modules/
$ sudo sh -c "find . | cpio -o -H newc | gzip > $HOME/microkvm/initramfs.gz"
$ sudo chown $(id -un):$(id -gn) ~/microkvm/initramfs.gz

# Verify inclusion
$ zcat ~/microkvm/initramfs.gz | cpio -t | grep microkvm_pci
```

**4. Boot and verify**

```bash
$ cd ~/microkvm
$ ./microkvm
```

After boot, run `insmod` → `lsmod` → `rmmod` in the guest as shown under Output.

### driver/microkvm_pci.c

```c
#include <linux/module.h>
#include <linux/pci.h>

/* Must match VMM's pci.h definitions */
#define MICROKVM_VENDOR  0x1234
#define MICROKVM_DEVICE  0x0001

/* Called when PCI core finds a device matching our ID table */
static int microkvm_probe(struct pci_dev *pdev, const struct pci_device_id *ent)
{
    dev_info(&pdev->dev, "microkvm_pci: probe called\n");
    return 0;
}

/* Called on rmmod or device removal */
static void microkvm_remove(struct pci_dev *pdev)
{
    dev_info(&pdev->dev, "microkvm_pci: remove called\n");
}

static const struct pci_device_id microkvm_pci_ids[] = {
    { PCI_DEVICE(MICROKVM_VENDOR, MICROKVM_DEVICE) },
    { 0, }  /* Sentinel—end of table */
};
MODULE_DEVICE_TABLE(pci, microkvm_pci_ids);
```

`PCI_DEVICE()` specifies vendor/device IDs. It sets subvendor/subdevice to `PCI_ANY_ID` and class_mask to 0, excluding subsystem IDs and class from the matching criteria.

```c
static struct pci_driver microkvm_pci_driver = {
    .name     = "microkvm_pci",
    .id_table = microkvm_pci_ids,
    .probe    = microkvm_probe,
    .remove   = microkvm_remove,
};
module_pci_driver(microkvm_pci_driver);

MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("microkvm PCI device driver");
```

## Output

```
/ # insmod /lib/modules/microkvm_pci.ko
microkvm_pci: loading out-of-tree module taints kernel.
microkvm_pci 0000:00:00.0: microkvm_pci: probe called
/ # lsmod
Module                  Size  Used by    Tainted: G
microkvm_pci           12288  0
/ # rmmod microkvm_pci
microkvm_pci 0000:00:00.0: microkvm_pci: remove called
```

`probe called` shows that the IDs matched and `probe()` ran; `lsmod` confirms module loading; `remove called` shows `remove()` running during unload.

> **Note:** At this stage, the driver has only *attached*. Device enablement and BAR access come in Step 30.

> **Note:** "taints kernel" is normal for an out-of-tree module. It marks the kernel for debugging purposes and is not an error.

## Key insight

A PCI driver is fundamentally an ID table plus two callbacks. The kernel PCI subsystem handles bus scanning, ID matching, and lifecycle management. The driver declares what it supports and provides probe/remove. This structure is shared by simple educational modules and production NVMe/NIC drivers.

## What this step teaches

| Concept | How it appears here |
|------|---------------|
| pci_device_id table | Match Vendor/Device IDs, just as physical drivers do |
| probe/remove | Device lifecycle callbacks |
| module_pci_driver | Macro removing init/exit boilerplate |
| Out-of-tree build | `make -C $(KDIR) M=$(PWD) modules` |
| Module.symvers | Kernel symbol table needed for module linking |
| ID matching and binding | A matching ID and successful probe bind the driver to the device |
